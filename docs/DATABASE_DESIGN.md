## Primary Key Strategy

All tables use UUID primary keys generated by `gen_random_uuid()`.

Exception: `profiles.id` uses the same UUID as `auth.users.id` from Supabase Auth.

## Table Definitions

---

### Table: `profiles`

**Purpose:** Stores the student's academic identity and profile. Links to Supabase Auth via shared UUID.

**Ownership:** Student-owned | **Privacy:** Private

| Column | Type | Required | Default | Notes |
|---|---|---|---|---|
| `id` | UUID | Yes | — | PK. Same as `auth.users.id`. |
| `full_name` | TEXT | Yes | — | Student's full name |
| `student_id` | TEXT | Yes | — | University student ID. UNIQUE. |
| `department` | TEXT | Yes | — | e.g., "Computer Science and Engineering" |
| `batch` | TEXT | Yes | — | e.g., "2021", "2022" |
| `section` | TEXT | Yes | — | e.g., "A", "B" |
| `current_semester` | TEXT | Yes | — | e.g., "Fall 2025", "Spring 2026" |
| `created_at` | TIMESTAMPTZ | Yes | `now()` | Creation timestamp |
| `updated_at` | TIMESTAMPTZ | Yes | `now()` | Last update timestamp |

**Foreign Keys:**
- `id` → `auth.users(id)` ON DELETE CASCADE

**Unique Constraints:**
- `student_id` — no two students share the same university ID

**Indexes:**
- PK on `id`
- Unique index on `student_id`
- Composite index on `(department, batch, section, current_semester)` — for routine lookups

**Delete behavior:** CASCADE from `auth.users` deletion

---

### Table: `courses`

**Purpose:** Shared course catalog. Not owned by any student. Reference data.

**Ownership:** System-managed | **Privacy:** Shared (read-only for students)

| Column | Type | Required | Default | Notes |
|---|---|---|---|---|
| `id` | UUID | Yes | `gen_random_uuid()` | PK |
| `code` | TEXT | Yes | — | Course code. UNIQUE. e.g., "CSE101" |
| `name` | TEXT | Yes | — | Full course name |
| `description` | TEXT | No | NULL | Optional description |
| `credit_hours` | INTEGER | No | NULL | Credit hours |
| `department` | TEXT | No | NULL | Offering department |
| `created_at` | TIMESTAMPTZ | Yes | `now()` | Creation timestamp |
| `updated_at` | TIMESTAMPTZ | Yes | `now()` | Last edit timestamp. Added in STEP 37. |

**Foreign Keys:** None

**Unique Constraints:**
- `code` — no two courses share the same code

**Indexes:**
- PK on `id`
- Unique index on `code`
- Index on `department`

**Delete behavior:** RESTRICT if enrollments exist; SET NULL on `class_routine_entries.course_id`

---

### Table: `enrollments`

**Purpose:** Join table implementing the M:N Student ↔ Course relationship. Records which student is in which course, in which academic period.

**Ownership:** Student-owned | **Privacy:** Private

| Column | Type | Required | Default | Notes |
|---|---|---|---|---|
| `id` | UUID | Yes | `gen_random_uuid()` | PK |
| `student_id` | UUID | Yes | — | FK to `profiles.id` |
| `course_id` | UUID | Yes | — | FK to `courses.id` |
| `academic_period` | TEXT | Yes | — | e.g., "Fall 2025" |
| `status` | TEXT | Yes | `'active'` | `'active'`, `'completed'`, `'dropped'` |
| `created_at` | TIMESTAMPTZ | Yes | `now()` | Creation timestamp |
| `updated_at` | TIMESTAMPTZ | Yes | `now()` | Last status change timestamp. Added in STEP 37. |

**Foreign Keys:**
- `student_id` → `profiles(id)` ON DELETE CASCADE
- `course_id` → `courses(id)` ON DELETE RESTRICT

**Unique Constraints:**
- `(student_id, course_id, academic_period)` — no duplicate enrollment in same course in same term

**Check Constraints:**
- `status IN ('active', 'completed', 'dropped')`

**Indexes:**
- PK on `id`
- Index on `student_id`
- Index on `course_id`
- Unique composite index on `(student_id, course_id, academic_period)`

**Delete behavior:** CASCADE on student delete; RESTRICT on course delete

---

### Table: `class_routine_entries`

**Purpose:** Individual class schedule time slots. Shared by academic group (Department + Batch + Section + Semester). One row = one scheduled class session.

**Ownership:** System-managed | **Privacy:** Shared by academic group

**Academic Group Pattern:** No separate `academic_groups` table. Each row carries `(department, batch, section, semester)` fields. Student's routine is found by composite match against profile fields.

| Column | Type | Required | Default | Notes |
|---|---|---|---|---|
| `id` | UUID | Yes | `gen_random_uuid()` | PK |
| `department` | TEXT | Yes | — | Academic group identifier |
| `batch` | TEXT | Yes | — | Academic group identifier |
| `section` | TEXT | Yes | — | Academic group identifier |
| `semester` | TEXT | Yes | — | Academic group identifier |
| `course_id` | UUID | No | NULL | FK to `courses.id`. Nullable — see `course_name_override`. |
| `course_name_override` | TEXT | No | NULL | Text fallback if course not yet in `courses` table |
| `day_of_week` | TEXT | Yes | — | `'Monday'` through `'Sunday'` |
| `start_time` | TIME | Yes | — | Class start time |
| `end_time` | TIME | Yes | — | Class end time |
| `room` | TEXT | No | NULL | Room or location |
| `instructor_name` | TEXT | No | NULL | Instructor name |
| `created_at` | TIMESTAMPTZ | Yes | `now()` | Creation timestamp |

**Foreign Keys:**
- `course_id` → `courses(id)` ON DELETE SET NULL

**Unique Constraints:**
- When `course_id IS NOT NULL`: `(department, batch, section, semester, course_id, day_of_week, start_time)` — standard unique index
- When `course_id IS NULL`: partial unique index on `(department, batch, section, semester, course_name_override, day_of_week, start_time)` — prevents duplicate null-course entries at same slot

> **Note (STEP 37 correction):** PostgreSQL NULL ≠ NULL in unique indexes, so the original single unique constraint on `(department, batch, section, semester, course_id, day_of_week, start_time)` would not prevent duplicate rows when `course_id` is NULL. Two separate index strategies are required.

**Check Constraints:**
- `day_of_week IN ('Monday', 'Tuesday', 'Wednesday', 'Thursday', 'Friday', 'Saturday', 'Sunday')`
- `course_id IS NOT NULL OR course_name_override IS NOT NULL` — at least one course identification field must be present

**Indexes:**
- PK on `id`
- Composite index on `(department, batch, section, semester)` — academic group lookup
- Partial unique index on `(department, batch, section, semester, course_id, day_of_week, start_time)` WHERE `course_id IS NOT NULL`
- Partial unique index on `(department, batch, section, semester, course_name_override, day_of_week, start_time)` WHERE `course_id IS NULL`
- Index on `day_of_week`
- Index on `course_id`

**Delete behavior:** SET NULL on course delete

**Implementation note (STEP 37):** The UI for profile setup must use controlled dropdown inputs for department, batch, section, and semester to ensure text values match exactly between `profiles` and `class_routine_entries`. Free-text input for these fields risks lookup failures.

### Table: `conversations`

**Purpose:** An AI chat session owned by a student. Contains many messages.

**Ownership:** Student-owned | **Privacy:** Private

| Column | Type | Required | Default | Notes |
|---|---|---|---|---|
| `id` | UUID | Yes | `gen_random_uuid()` | PK |
| `student_id` | UUID | Yes | — | FK to `profiles.id` |
| `title` | TEXT | No | NULL | Nullable. May be auto-generated or user-set. |
| `created_at` | TIMESTAMPTZ | Yes | `now()` | When conversation started |
| `updated_at` | TIMESTAMPTZ | Yes | `now()` | Updated on new message or rename |

**Foreign Keys:**
- `student_id` → `profiles(id)` ON DELETE CASCADE

**Indexes:**
- PK on `id`
- Index on `student_id`
- Composite index on `(student_id, updated_at DESC)` — recent conversations list

**Delete behavior:** CASCADE on student delete; CASCADE to `messages` on conversation delete

---

### Table: `messages`

**Purpose:** Individual chat messages within a conversation. Includes both student messages (`role = 'user'`) and AI responses (`role = 'assistant'`).

**Ownership:** Student-owned (through conversation) | **Privacy:** Private

| Column | Type | Required | Default | Notes |
|---|---|---|---|---|
| `id` | UUID | Yes | `gen_random_uuid()` | PK |
| `conversation_id` | UUID | Yes | — | FK to `conversations.id` |
| `role` | TEXT | Yes | — | `'user'` or `'assistant'` |
| `content` | TEXT | Yes | — | Message text. Cannot be empty. |
| `created_at` | TIMESTAMPTZ | Yes | `now()` | Used for ordering messages |

**Foreign Keys:**
- `conversation_id` → `conversations(id)` ON DELETE CASCADE

**Check Constraints:**
- `role IN ('user', 'assistant')`

**Notes:**
- No `student_id` FK. Ownership established through conversation chain.
- Messages are immutable after creation. No `updated_at`.
- Assistant messages are inserted by the server (service role) after receiving OpenAI response.
- RLS for messages uses a subquery through conversations: `conversation_id IN (SELECT id FROM conversations WHERE student_id = auth.uid())`
- RLS INSERT: Student-side clients (authenticated JWT) may only INSERT `role = 'user'`. Service role inserts `role = 'assistant'`. This prevents assistant message impersonation.

**Indexes:**
- PK on `id`
- Index on `conversation_id`
- Composite index on `(conversation_id, created_at ASC)` — ordered message retrieval

**Delete behavior:** CASCADE on conversation delete

---

### Table: `experiences`

**Purpose:** Student experience submissions. Private by default. May be promoted to Campus Memory through an explicit sharing decision.

**Ownership:** Student-owned | **Privacy:** Private by default

| Column | Type | Required | Default | Notes |
|---|---|---|---|---|
| `id` | UUID | Yes | `gen_random_uuid()` | PK |
| `student_id` | UUID | Yes | — | FK to `profiles.id` |
| `title` | TEXT | Yes | — | Short title |
| `content` | TEXT | Yes | — | Full submission text |
| `visibility` | TEXT | Yes | `'private'` | `'private'` or `'shared'` |
| `created_at` | TIMESTAMPTZ | Yes | `now()` | Submission timestamp |
| `updated_at` | TIMESTAMPTZ | Yes | `now()` | Last edit timestamp |

**Foreign Keys:**
- `student_id` → `profiles(id)` ON DELETE CASCADE

**Check Constraints:**
- `visibility IN ('private', 'shared')`

**Important rule:** Setting `visibility = 'shared'` does NOT automatically create a Campus Memory entry. The server must explicitly create the Campus Memory row as a separate application-level action.

**Indexes:**
- PK on `id`
- Index on `student_id`
- Index on `visibility`

**Delete behavior:** CASCADE on student delete; `campus_memories.source_experience_id` SET NULL on experience delete

---

### Table: `campus_memories`

**Purpose:** The shared knowledge pool. Curated entries available for AI retrieval. Not owned by any individual student.

**Ownership:** System-managed | **Privacy:** Shared (all authenticated students can read)

| Column | Type | Required | Default | Notes |
|---|---|---|---|---|
| `id` | UUID | Yes | `gen_random_uuid()` | PK |
| `title` | TEXT | Yes | — | Short title |
| `content` | TEXT | Yes | — | Full content used for AI context retrieval |
| `category` | TEXT | No | NULL | e.g., `'academic'`, `'campus_life'`, `'advice'` |
| `tags` | TEXT[] | No | NULL | Array of keyword tags for retrieval |
| `source_experience_id` | UUID | No | NULL | Nullable FK to `experiences.id`. Traces origin. SET NULL on experience delete. |
| `created_at` | TIMESTAMPTZ | Yes | `now()` | When entry was added |
| `updated_at` | TIMESTAMPTZ | Yes | `now()` | When entry was last curated |

**Foreign Keys:**
- `source_experience_id` → `experiences(id)` ON DELETE SET NULL

**Unique Constraints:**
- `source_experience_id` — UNIQUE (nullable). PostgreSQL UNIQUE on a nullable column allows multiple NULL values but enforces that each non-null value appears at most once. This enforces: one experience → at most one campus memory. System-created entries (no source experience) may coexist freely with `source_experience_id = NULL`. **[Added in STEP 37]**

**Indexes:**
- PK on `id`
- UNIQUE index on `source_experience_id` (auto-created by UNIQUE constraint)
- Index on `category`
- GIN index on `tags` (array search)
- Full-text search index: GIN index on `to_tsvector('english', content)` — language confirmed as `'english'` in STEP 37

**Delete behavior:** Source experience delete → SET NULL on `source_experience_id` (campus memory survives)

**FTS language (STEP 37 decision):** The tsvector full-text search index uses the `'english'` language configuration. This provides English-language stemming and stop-word filtering. If campus content is primarily in another language, this setting must be updated before SQL implementation.

## Campus Memory Storage Direction

Campus Memory is stored as application data in the `campus_memories` table in PostgreSQL.

Campus Memory is not model training or LLM fine-tuning.

---

## Retrieval Direction

Initial retrieval uses PostgreSQL full-text search (`tsvector`) on `campus_memories.content`.

FTS language configuration: `'english'` (decided in STEP 37).

Tag filtering via GIN index on `campus_memories.tags` is also available.

Category filtering via index on `campus_memories.category` is also available.

pgvector may be evaluated later if retrieval quality is insufficient. It is excluded from MVP.

Exact retrieval algorithm: Not decided yet (planned for AI system implementation step).

## What Is NOT A Table

| Concept | Why Not a Table |
|---|---|
| Department | TEXT field on `profiles` — no separate table needed in MVP |
| Batch | TEXT field on `profiles` — same reason |
| Section | TEXT field on `profiles` — same reason |
| Semester | TEXT field on `profiles` and `enrollments` — same reason |
| Academic Group | Composite of four fields — composite lookup, no separate table |
| AI Response | Stored as assistant `messages` row — no separate table |
| Retrieved Memory Context | Derived at request time — not persisted |
| AI Context / Prompt Payload | Derived at request time — not persisted |
